### 4.2 Investigation needed: how did `test-dirty-fork.sh` content leak into the host repo?

I never explicitly ran `test-dirty-fork.sh` — only `test-upgrade-cycle.sh`. Yet the host repo ended up with `docs/ARCHITECTURE.md` (Next.js/Supabase content, ~555 bytes) and `docs/API.md` ("# WIP: API Documentation\nTODO: Document all endpoints") — both of which match `test-dirty-fork.sh`:127-153 and 267-269 exactly, and neither of which appears anywhere in `test-upgrade-cycle.sh`.

Two hypotheses for an upstream agent to investigate:

1. **`run_upgrade` invokes `template-sync.sh` inside the test fork, and something in that path executes `test-dirty-fork.sh` indirectly** (e.g., a pre-push hook, a sync-script side effect, an rsync-restored stale state). If `cd "$test_dir"` silently failed but `apply_scenario` still ran (no `pwd` assertion), the writes land in the host repo. But this only explains `test-upgrade-cycle.sh` scenarios; `test-dirty-fork.sh` content is unexplained.

## 5. Insights and Learnings

- **Bash functions invoked via `$()` must treat stdout as a single-valued return channel.** Every line of output from inside the function — including unexpected git complaints, mkdir confirmations, or shellcheck-suppressed errors — gets concatenated into the captured value. Route side-effect output to stderr (`>&2`) or `/dev/null`, write the actual return value last. This is bug #4 above, but it's a general principle worth memorizing.
- **`cd "$dir" || exit` is necessary but not sufficient.** It catches the case where `cd` fails outright, but not the case where `cd` "succeeds" to an unintended directory (e.g., when `$dir` is empty/whitespace and bash interprets it as a no-op, or when the captured value is multi-line garbage that bash de-quotes weirdly). Add a `pwd` assertion against the expected path inside any function that writes via relative paths.
- **Test helpers that run inside the host repo are inherently dangerous.** The safest pattern is "refuse to run unless cwd is clean and outside the host repo," or alternatively "run inside a `cd /tmp/...` with absolute paths only." `test-upgrade-cycle.sh` violates both — it rsync's the host repo into a temp dir, but its scenario fixtures use relative paths that depend on the cwd staying correct, and bugs #3 and #4 break that invariant silently.
- **Codespaces `GITHUB_TOKEN` is local-repo-scoped only.** Any cross-repo write (issue create, PR review, comment, label) will fail with "Resource not accessible by integration." `scripts/report-issue.sh` already knows this and provides a fallback path; the takeaway is that any cross-repo automation needs an explicit fine-grained PAT, not the default Codespaces token.
- **`/upgrade` writes a bare slug into `.agile-flow-version` but a separate file `.agile-flow-meta/upstream` stores the same value.** Two fields for the same fact is fragile. The fork also has `.agile-flow-meta/version` (plain `v1.0.10`) and `.agile-flow-version` (JSON with `version` field). Four pieces of state describing two facts (upstream identity, current version). The duplication likely explains why bug #6 was not caught — the producer wrote both, and the consumer happened to read the wrong one.
- **Pre-filled GitHub issue URLs have a practical body-length limit around 8 KB.** Anything longer needs a "open URL with title+labels only, paste body from disk" workflow.
